The problem it solves

Epidemiological surveillance systems issue reactive alerts: confirmed case counts arrive 2–3 weeks late, by which time transmission is already established.

This project builds a predictive early warning system with a 4-week horizon, using exclusively open public data. The system estimates cases for weeks $t+1$ to $t+4$ using information available up to week $t$.

A useful prediction enables: fumigation and vector control, hospital capacity planning, and preventive public communication.

🕸️ EpiGNN — Exploratory extension
Neural network over spatial graph.
Each department = node. Edges via geographic k-nearest neighbours (k=5).

2× GCNConv (30→64→32) · fc(32→4)
HuberLoss(δ=5) · 80 epochs · dropout 0.3

447 nodes · 208 training graphs.
Validation strategy — Walk-Forward
For each year $t$ ∈ {2020, ..., 2025}:
  ① Train on data up to year $t-1$
  ② Predict full year $t$

Project decisions and insights
Insight 1 — 2024 Outbreak
The 2024 outbreak was 10× the historical maximum. No model trained on 2018–2023 could anticipate that magnitude. This does not invalidate the model: the relative improvement over the baseline remains statistically significant (non-overlapping 95% CIs in 5 of 6 walk-forward years).
Insight 2 — Epidemiological lags dominate
The 5 most important variables are case lags, not climate variables. Recent cases directly capture the state of community transmission (fumigation coverage, susceptible density) that environmental variables cannot capture with equal specificity.
Insight 3 — EpiGNN and the spatial signal
EpiGNN achieves MAE 14.3 in 2024 (best absolute) but MAPE ~99% in low-burden years. Conclusion: the spatial graph adds information when there are pronounced epidemic gradients between neighbouring departments. In low-transmission endemic years, the spatial signal adds insufficient value.
Insight 4 — Data leakage in feature selection
Feature selection must be done ONLY with training data (2018–2019). Including 2024 causes the model to "choose" variables that already know the outbreak, artificially inflating metrics. This was corrected during development and constitutes a methodological contribution.
Insight 5 — Prospective temporal validation
Random cross-validation would have produced ~30% better metrics, but illusorily. Walk-forward validation exposes real performance under operational conditions. This design decision is what makes the work publishable in a public health journal.
Process learning
Integrating 5 heterogeneous data sources took longer than training the models. Data quality (especially SNVS schema normalisation) was critical. Model complexity must be justified by statistically significant improvement, not just numerical improvement.
When to use LightGBM vs EpiGNN?
⚡ LightGBM — recommended for operational use
Stable across all walk-forward years. Fast to train and retrain. Interpretable with SHAP. Does not require GeoJSON geometries. Ideal for weekly real-time alerts.
🕸️ EpiGNN — recommended for outbreak analysis
Best absolute MAE in extreme outbreaks. Captures inter-departmental propagation. Requires GeoJSON geometries and GPU for scalability. Useful for identifying which neighbouring departments will spread the virus.

What makes this work different
1. Departmental scale
First walk-forward model at departmental level with real SNVS data. Previous literature in Argentina was at provincial level.
2. Real prospective validation
Walk-forward with bootstrap 95% CI. No random cross-validation that artificially inflates metrics.
3. 100% open data
SNVS + NASA POWER + INDEC. Reproducible without licences or institutional agreements.
4. Spatial graph
EpiGNN models inter-departmental spread: unique ability to detect where an outbreak originated.

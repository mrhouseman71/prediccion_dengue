El problema que resuelve

Los sistemas de vigilancia epidemiológica emiten alertas reactivas: el conteo de casos confirmados llega con 2–3 semanas de rezago, cuando la transmisión ya está establecida.

Este proyecto construye un sistema de alerta temprana predictiva con horizonte de 4 semanas, usando exclusivamente datos públicos y abiertos. El sistema estima casos para la semana $t+1$ a $t+4$ usando información disponible hasta la semana $t$.

Una predicción útil permite anticipar: fumigación y descacharrización, capacidad hospitalaria y comunicación preventiva a la población.

Estrategia de validación — Walk-Forward

  ① Entrenar con datos hasta año $t-1$
  ② Predecir el año $t$ completo

Decisiones e insights del proyecto
Insight 1 — Brote 2024
El brote de 2024 fue 10× el máximo histórico. Ningún modelo entrenado en 2018–2023 podía anticipar esa magnitud. Esto no invalida el modelo: la mejora relativa sobre el baseline sigue siendo estadísticamente significativa (IC 95% no solapados en 5 de 6 años del walk-forward).
Insight 2 — Los rezagos epidemiológicos dominan
Las 5 variables más importantes son rezagos de casos, no variables climáticas. Los casos recientes capturan directamente el estado de transmisión comunitaria (coberturas de fumigación, densidad de susceptibles) que las variables ambientales no capturan con igual especificidad.
Insight 3 — EpiGNN y la señal espacial
EpiGNN obtiene MAE 14.3 en 2024 (mejor absoluto) pero MAPE ~99% en años de baja carga. Conclusión: el grafo espacial aporta información cuando existen gradientes epidémicos pronunciados entre departamentos vecinos. En años endémicos de baja transmisión, la señal espacial no agrega valor suficiente.
Insight 4 — Data leakage en feature selection
La selección de features debe hacerse SOLO con datos de entrenamiento (2018–2019). Si se incluye 2024, el modelo "elige" variables que ya conocen el brote, inflando artificialmente las métricas. Este problema se corrigió durante el desarrollo y es una contribución metodológica del trabajo.
Insight 5 — Validación temporal prospectiva
La validación cruzada aleatoria habría producido métricas ~30% mejores, pero ilusoriamente. La validación walk-forward expone el rendimiento real en condiciones operacionales. Esta decisión diseño es lo que hace al trabajo publicable en una revista de salud pública.
Aprendizaje del proceso
Integrar 5 fuentes de datos heterogéneas requirió más tiempo que entrenar los modelos. La calidad del dato (especialmente la normalización de esquemas SNVS) fue determinante. La complejidad del modelo debe justificarse con mejora estadísticamente significativa, no solo con mejora numérica.
¿Cuándo usar LightGBM vs EpiGNN?
⚡ LightGBM — recomendado para uso operacional
Estable en todos los años del walk-forward. Rápido de entrenar y re-entrenar. Interpretable con SHAP. No requiere geometrías GeoJSON. Ideal para alertas semanales en tiempo real.
🕸️ EpiGNN — recomendado para análisis de brotes
Mejor MAE absoluto en brotes extremos. Captura propagación interdepartamental. Requiere geometrías GeoJSON y GPU para escalabilidad. Útil para identificar qué departamentos vecinos propagarán el virus.

Diferencial de este trabajo
1. Escala departamental
Primer modelo walk-forward a nivel departamental con datos reales del SNVS. La literatura previa en Argentina era a nivel provincial.
2. Validación prospectiva real
Walk-forward con IC 95% bootstrap. No validación cruzada aleatoria que infla métricas artificialmente.
3. 100% datos abiertos
SNVS + NASA POWER + INDEC. Reproducible sin licencias ni acuerdos institucionales.
4. Grafo espacial
EpiGNN modela la propagación interdepartamental: capacidad única para detectar dónde se originó un brote.

¿Cómo "vender" este producto?
"Cada semana de anticipación equivale a miles de hogares fumigados a tiempo."

El sistema transforma datos públicos disponibles en una ventaja operacional de 4 semanas para cualquier sistema de salud provincial. El costo de implementación es cero: datos abiertos, modelos de código abierto, infraestructura Colab/Google Drive.
